# 003 · Правка текста и дообучение — Proposal

**Review:** ждёт владельца. Отклонения при реализации — в [`implementation.md`](implementation.md).

## Коротко

Две части одного обновления.

**Правка карточки и дообучение.** В режиме вывода Card карточка в плашке открывается на правку
(`E` или кнопка), текст редактируется прямо в острове или пилюле, `⌘↩` сохраняет. Приложение
сравнивает распознанный текст с исправленным, находит исправления написания терминов и само
заводит записи словаря «хедер → Header». Запись правит все следующие диктовки и уходит в prompt
Whisper — слово начинает распознаваться верно. Что добавилось, видно в карточке и отменяется
одним нажатием.

**Правка выделенного голосом.** Выделил текст в любом приложении, нажал ⌃⌥E, сказал «перепиши
короче» — выделенное заменено. Диктовка здесь не текст, а инструкция; работает на локальной
языковой модели, которая уже есть в приложении.

## Часть 1. Правка карточки

### Что меняется на экране

```
┌─ остров, режим Card ─────────────────────────────┐   ┌─ он же на правке ────────────────────────────────┐
│ ≡                                            ✕   │   │ ≡                                            ✕   │
│                                                  │   │ ┌──────────────────────────────────────────────┐ │
│ Поправь хедер в компоненте, он дёргается         │   │ │ Поправь Header в компоненте, он дёргается▌   │ │
│ при каждом рендере.                              │   │ │                                              │ │
│                                                  │   │ └──────────────────────────────────────────────┘ │
│ [ Copy ⌘C ] [ Paste V ] [ Edit E ]               │   │ [ Save ⌘↩ ] [ Cancel esc ]                       │
└──────────────────────────────────────────────────┘   └──────────────────────────────────────────────────┘
                                                        после сохранения, на 4 секунды:
                                                        ✓ Added to dictionary · хедер → Header   ✕
```

В пилюле то же самое внутри пузыря. Обе плашки рисуют карточку одним общим видом `OverlayCard`
(сейчас код карточки продублирован в `IslandView` и `PillView`) — иначе правку пришлось бы
писать дважды и чинить дважды.

### Фокус клавиатуры

Главная техническая трудность. `OverlayPanel` намеренно не становится ключевым окном
(`canBecomeKey == false`): плашка висит поверх чужого приложения и не должна забирать у него
фокус. Для ввода фокус нужен.

Решение: панель создана со стилем `.nonactivatingPanel`, а это ровно тот случай, когда окно может
стать ключевым, **не активируя своё приложение**. Значит:

- `canBecomeKey` становится вычисляемым: `true` только пока идёт правка.
- Вход в правку: `panel.editing = true; panel.makeKey()`. saytype остаётся неактивным, целевое
  приложение — фронтальным, но клавиши идут в карточку.
- Выход: `panel.editing = false; panel.makeFirstResponder(nil)`, затем целевому приложению
  возвращается ключевое окно через `NSRunningApplication.activate()` (то же, что делает
  «Paste again» в истории). Если приложение не найдено — `orderOut` + `orderFrontRegardless`,
  после чего macOS сама отдаёт фокус ниже лежащему окну.
- Перехватчик клавиш карточки (`KeyInterceptor`, глотает `V`, `⌘C`, `esc` из любого приложения)
  на время правки останавливается: иначе буква «V» вставляла бы текст вместо того, чтобы
  напечататься.

Риск: если ключевое окно не вернётся, человек окажется с плашкой, которая ест клавиши. Поэтому
выход из правки происходит и по `esc`, и по клику мимо карточки, и при закрытии карточки, и
принудительно, если карточка исчезает по любой причине.

### Что считается дообучением

Сравниваем три текста: `raw` (что услышал Whisper), `text` (что показала карточка) и `edited`
(что стало после правки). Выравнивание `text` ↔ `edited` по словам даёт участки, которые человек
изменил; для каждого участка `HistoryCorrection.heard(raw:text:words:)` — он уже есть и уже
покрыт тестами — говорит, какими словами это было в сыром распознавании.

Дальше фильтр. В словарь идут **только исправления написания**, потому что запись словаря —
это регулярка, которая применяется ко всем будущим диктовкам; мусор там дороже пропущенной пользы.
Участок принимается, когда выполнено одно из:

| Правило | Пример | Запись |
|---|---|---|
| Отличие только в регистре | `github` → `GitHub` | без «услышано», только написание |
| Кириллица → латиница, и написания звучат похоже | `хедер` → `Header` | `хедер → Header` |
| Латиница → латиница, буквы те же без разделителей | `use effect` → `useEffect` | `use effect → useEffect` |

«Звучат похоже» считается так: кириллическая сторона транслитерируется по звуку
(`хедер` → `heder`, `юз эффект` → `yuzeffekt`), у обеих сторон убираются небуквенные символы,
считается расстояние Левенштейна, похожесть = `1 − d / max(len)`. Порог **0.5**, а если написанное
слово уже известно приложению (словарь пользователя, встроенный словарь, идентификаторы из папок
проектов, `Words.isCodeLike`) — **0.3**: там мы не угадываем термин, а лишь учим, как он звучит.

Замеры порога на реальных парах:

| Услышано | Написано | Похожесть | Итог |
|---|---|---|---|
| хедер | Header | 0.83 | принято |
| версель | Vercel | 0.83 | принято |
| супабейс | Supabase | 0.63 | принято |
| юз эффект | useEffect | 0.56 | принято |
| некст джей эс | Next.js | 0.33 | принято по порогу известного термина |
| поправь это | fix this | 0.20 | отклонено |
| сделай список | make a list | 0.17 | отклонено |

Сверх этого участок отклоняется, если одна из сторон пуста (чистая вставка или удаление слов),
длиннее трёх слов или 40 символов, содержит конец предложения или перевод строки. За одну правку
в словарь уходит не больше пяти записей.

Код: `VMCore/EditLearning.swift`, `EditLearning.corrections(raw:text:edited:knownTerms:)` →
`[DictionaryEntry]`. Выравнивание слов (LCS) переезжает из приватного метода `HistoryCorrection`
в `Words.alignment(_:_:)`, чтобы им пользовались оба места. Чистая функция — покрывается юнит-тестами
без интерфейса.

### Что ещё меняется после сохранения

- Текст карточки заменяется исправленным: `V`, `⌘C` и перетаскивание отдают уже правку.
- Запись в истории обновляется (`HistoryStore.update(id:text:)`), поле `raw` остаётся прежним —
  вкладка «Changes» продолжает показывать разницу с сыром распознаванием, а правка видна как
  часть изменений.
- Записи словаря добавляются через существующий `addCorrection` с источником `.history`
  (в разделе Dictionary столбец Source покажет «from history»).
- Полоска «Added to dictionary · хедер → Header» живёт 4 секунды; ✕ убирает добавленные записи
  обратно. Больше двух записей — «Added to dictionary · 3 terms» с раскрытием по наведению.

### Настройка

В разделе Key and overlay, в блоке After recording, под карточками режимов появляется
переключатель **Learn from edits** — «fixed terms go to the dictionary», по умолчанию включён.
Он гаснет, когда выбран режим не Card, — так же, как уже гаснет «Return after paste» вне режима
Paste. Правка карточки работает всегда; переключатель управляет только словарём.

Место в блоке есть: строка «Return after paste» и переключатель встают в один ряд.

## Часть 2. Правка выделенного голосом

### Поток

```
⌃⌥E ──► читаем выделение ──► запись (hands-free) ──► Whisper ──► модель: инструкция + фрагмент ──► вставка поверх выделения
         пусто → «Nothing selected»        ⌃⌥E / esc                 модель выключена → «Model is off»
```

1. **Чтение выделения.** Сначала Accessibility: у сфокусированного элемента спрашивается
   `kAXSelectedTextAttribute` — ничего не трогает и работает в нативных приложениях и в Xcode.
   Если приложение атрибут не отдаёт (терминалы, Electron), запасной путь — снимок буфера
   обмена, программное `⌘C`, ожидание изменения `changeCount` до 400 мс, чтение, восстановление
   буфера. Не изменился `changeCount` — значит, выделения нет. Поле пароля и
   `IsSecureEventInputEnabled()` не читаются никогда.
2. **Запись.** Тот же конвейер, что у обычной диктовки, но hands-free: второе нажатие ⌃⌥E или
   клавиша записи заканчивают, `esc` отменяет. Плашка показывает тег «Selection» и первые слова
   выделенного, чтобы было видно, над чем работаем.
3. **Модель.** Новый стиль `RewriteRequest.Rewrite.selection`: в системном промпте — общие
   правила (не выдумывать, сохранять идентификаторы, отвечать только текстом), в пользовательском
   — инструкция и фрагмент в тегах. Валидатор для этого стиля проверяет только пустоту и
   разумную длину: человек прямо просит изменить слова, значит проверка «слова не изменились»
   здесь неверна.
4. **Вставка.** Через тот же `Paster.paste`: выделение в приложении никуда не делось, `⌘V` его
   заменяет, буфер восстанавливается, `⌘Z` в приложении возвращает исходный текст. Если в
   настройках выбран режим Card, результат приходит карточкой с кнопкой «Replace» — и его можно
   поправить руками по части 1.

### Границы

- Нужна языковая модель. Выключена или не загружена — плашка говорит «Model is off» и открывает
  раздел Model по клику. Ничего не портится.
- Длина выделения ограничена 6000 символами (примерно 1500 токенов): дальше локальная модель
  думает дольше таймаута.
- Сочетание по умолчанию ⌃⌥E, рядом с уже существующими ⌃⌥V, ⌃⌥C, ⌃⌥M; переназначается в
  Key and overlay. Чтобы в строке сочетаний поместилось четвёртое, «Copy last dictation»
  сокращается до «Copy last».

## Риски

| Риск | Что делаем |
|---|---|
| Фокус не вернулся в приложение после правки | Выход из правки по esc, по клику мимо, по закрытию карточки; запасной путь `orderOut` + `orderFrontRegardless` |
| В словарь попала ерунда и портит все диктовки | Жёсткий фильтр, не больше пяти записей за правку, видимый список добавленного, отмена одним нажатием, переключатель в настройках |
| `⌘C` в запасном пути читает старый буфер, если выделения нет | Решение по `changeCount`, а не по содержимому; буфер восстанавливается всегда |
| Модель испортила выделенный текст | `⌘Z` в приложении; валидатор режет пустое и слишком длинное; режим Card показывает результат до замены |
| Карточка на правке перекрывает окно и мешает | Плашка и так поверх всего; правка заканчивается по esc и по клику мимо |

## Что не делаем

- Не дообучаем веса Whisper. Дообучение идёт в словарь и в prompt — это единственное, что даёт
  эффект сразу и не ломается при обновлении macOS.
- Не правим карточку голосом: продиктовать латинское написание невозможно, «на Header»
  распознаётся как «на хедер».
- Не переносим автоматическое обучение в раздел History: там уже есть ручной выбор слов. Общий
  код (`EditLearning`) лежит в `VMCore`, подключить History можно потом одной строкой.
