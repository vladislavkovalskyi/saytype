# 001 · voicemode MVP — Proposal

**Review:** согласовано владельцем. Отклонения при реализации — в [`implementation.md`](implementation.md).

## Коротко

Нативное приложение на Swift (SwiftUI + AppKit), macOS 26+, только Apple Silicon. Живёт в строке
меню. Речь распознаёт WhisperKit с моделью Whisper large-v3-turbo прямо на Mac. Текст оформляет
локальный конвейер: словарь терминов, чистка паразитов, паузы → абзацы, «во-первых…» → список и,
для длинных фраз, маленькая LLM через MLX. LLM размечает предложения, а не пишет текст, поэтому
слова не меняются. Вставка — через буфер обмена и ⌘V с
восстановлением буфера. Плашка — неактивирующееся окно с Liquid Glass, в двух стилях: пилюля
снизу или остров у выреза камеры.

Что изучили и почему выбрали именно это — в [`research.md`](research.md).

## Платформа и проект

- **Swift 6.3, SwiftUI + AppKit.** Настоящий Liquid Glass есть только в нативном UI. Electron и
  Tauri дают размытие, но не стекло macOS 26, и тяжелее для приложения, которое висит в фоне.
- **Deployment target — macOS 26.0.** API, появившиеся в macOS 27 (`NSGlassEffectView.effectIsInteractive`,
  `NSView.cornerConfiguration`), включаются через `#available(macOS 27, *)`, когда проект соберём
  Xcode 27. Сейчас установлен Xcode 26.6 — для MVP этого достаточно.
- **Проект описан в `project.yml` (XcodeGen).** `.xcodeproj` генерируется и в git не попадает:
  диффы читаемые, сборка из терминала через `xcodebuild`.
- **Подпись в разработке — сертификат Apple Development владельца.** Разрешения macOS
  (Accessibility, Input Monitoring) привязаны к подписи. Если пересобирать с разной подписью,
  они слетают, и перехват Fn молча перестаёт работать.
- **Приложение без песочницы (App Sandbox выключен).** Accessibility API и программное нажатие
  ⌘V в песочнице не работают. Mac App Store поэтому не рассматриваем.
- **Без иконки в Dock** (`LSUIElement`). Окна онбординга и настроек открываются как обычные.

## Как устроено

```
 Fn (CGEventTap) ──► DictationSession ◄──────────────── Overlay (pill | notch)
                          │   ▲                            ▲   живой текст, волна, состояния
                          ▼   │                            │
                    AudioCapture ──► TranscriptionEngine ──┘
                    16 кГц mono      WhisperKit + LiveAgreement
                                          │ финальный текст + таймкоды слов
                                          ▼
                                 FormattingPipeline
                         чистка → пунктуация → абзацы → LLM → валидатор
                                          │
                                          ▼
                         Output: вставка ⌘V | карточка в плашке | буфер
                                          │
                                          ▼
                                   History (SwiftData)
```

`DictationSession` — конечный автомат одной диктовки:
`idle → listening → finalizing → formatting → delivering → done`, плюс `cancelled` и `failed`.
Плашка и строка меню только отображают его состояние.

Модули в коде: `App`, `Onboarding`, `Settings`, `MenuBar`, `Overlay`, `Hotkey`, `Audio`,
`Transcription`, `Formatting`, `Output`, `History`, `Permissions`, `DesignSystem`.

## Распознавание

**Движок — WhisperKit** (пакет `argmax-oss-swift`, MIT). Whisper через Core ML на Neural Engine,
подключается через Swift Package Manager.

**Модель по умолчанию — `large-v3-v20240930_turbo_632MB`.** Это large-v3-turbo. На M3 Pro фраза в
4–7 секунд распознаётся за 1,2 с вместе со словарём терминов. Вариант `626MB` при том же качестве
медленнее: 2 с. Замеры — в [`implementation.md`](implementation.md).

**Язык.** По умолчанию принудительно `ru`: автоопределение на смешанной речи иногда
переключается на английский и переводит сказанное. В настройках: русский, английский, авто.

**Словарь терминов.** В `promptTokens` финального прохода уходит список терминов: сначала словарь
пользователя (`useEffect`, `Vercel`, `Supabase`), потом встроенные, до 240 символов. Живые
проходы идут без prompt: так они вдвое быстрее, а термины всё равно исправит финальный проход.

**Фильтр галлюцинаций.** Whisper на тишине выдумывает «Субтитры сделал DimaTorzok» и подобное.
Тишину по краям обрезаем, известные фразы вычищаем.

**Второй движок — Apple `DictationTranscriber` (ru-RU).** Системный, модель скачивать не нужно,
живой текст из коробки. Нужен в двух местах: онбординг, пока Whisper скачивается и готовится, и
запасной вариант, если модель Whisper не загрузилась. Качество на русском не проверено — это
тоже вопрос замера. Оба движка за протоколом `TranscriptionEngine`.

**Загрузка модели.** Не в бандле, а при первом запуске. Приложение в любом случае готовит модель
Core ML под конкретный чип, а после обновления macOS система этот кеш сбрасывает. Загрузка с
Hugging Face с зафиксированного коммита, с докачкой и проверкой SHA-256. После загрузки модель
всегда грузится из локальной папки, без обращений в сеть.

## Живой текст

Встроенный в WhisperKit `AudioStreamTranscriber` на русском даёт много «прыгающего» текста.
Поэтому свой цикл поверх того же API.

1. Пока Fn зажат, примерно раз в секунду заново распознаём звук с последней зафиксированной точки.
2. Слово фиксируется, когда два прохода подряд согласны (политика LocalAgreement-2 из
   `ufal/whisper_streaming`).
3. В плашке зафиксированные слова яркие, незафиксированные приглушены. Новые слова проявляются
   из лёгкого размытия.
4. На отпускание: фраза до ~30 с распознаётся целиком одним финальным проходом (так точнее).
   Длиннее — распознаётся только незафиксированный хвост, а зафиксированный текст идёт как prompt.

## Структура текста

Конвейер из стадий, каждая может быть пропущена. Всегда есть что вставить в пределах бюджета
времени.

| # | Стадия | Как | Время |
|---|---|---|---|
| 1 | Абзацы | пауза от 1,5 с после конца предложения по таймкодам слов → новый абзац | < 1 мс |
| 2 | Словарь | «юз эффект» → `useEffect`, «docker compose» → `Docker Compose`, до трёх слов подряд | < 5 мс |
| 3 | Паразиты | «эээ», «ммм» по умолчанию; «ну / типа / короче» — по настройке | < 1 мс |
| 4 | Список | «во-первых… во-вторых…» → вводная фраза с двоеточием и нумерованный список | < 1 мс |
| 5 | Умная структура | LLM Qwen3-1.7B (4 бита, MLX) ставит каждому предложению метку: продолжение абзаца, новый абзац, пункт списка. Текст собирается из меток | ~0,6 с, лимит 1,5 с |
| 6 | Валидатор | слова до и после совпадают по порядку, без учёта регистра и знаков. Можно убрать только «эээ» и «во-первых». Иначе — результат стадии 4 | < 5 мс |

**LLM не пишет текст.** Первая версия просила модель переписать текст со структурой. 0.8B
переписывала слова, 2B почти ничего не структурировала и тоже теряла слова. Разметка меток
работает быстрее (модель выдаёт по 3 токена на предложение) и не может изменить сказанное.

**LLM включается не всегда.** Короткой фразе «поправь useEffect в Header» списки и абзацы не
нужны. Стадия 5 срабатывает от 40 слов и если в тексте ещё нет списка. Модель загружается в
фоне, когда человек начинает говорить, и выгружается после 5 минут простоя. Если к концу
диктовки модель ещё не загрузилась, текст вставляется без неё.

**LLM — отдельная загрузка** («Умная структура», 944 МБ). Без неё работают стадии 1–4.

**Apple Foundation Models не подходят:** русский язык не поддерживается ни в macOS 26, ни в 27.

**RUPunct отложен.** Whisper со списком терминов в prompt ставит знаки и в длинных фразах. Вернёмся,
если записи владельца покажут обратное.

**Сырой и оформленный текст хранятся оба** в истории.

## Горячая клавиша

- **Fn зажат — запись, отпущен — готово.** Удержание Fn ловится через `CGEventTap` на
  `flagsChanged` (keycode 63). Обычные библиотеки хоткеев одиночный Fn не умеют.
- **Двойное нажатие Fn — запись без рук**, одиночное Fn её завершает. Отличаем удержание от
  нажатия по порогу ~300 мс. **Esc отменяет** диктовку.
- **Переназначение:** правый ⌥, правый ⌘ или любое сочетание через `KeyboardShortcuts` 3.1 (MIT).
  Сочетания работают даже при включённом Secure Input, когда event tap глохнет.
- **Конфликт с системой.** По умолчанию Fn открывает системную диктовку или эмодзи. Онбординг
  проверяет настройку «Нажатие клавиши 🌐» и ведёт в Системные настройки, если там не «Ничего не
  делать».
- **Secure Input** (поле пароля, Secure Keyboard Entry в терминале) детектируется через
  `IsSecureEventInputEnabled()`. Плашка честно говорит, почему не слушает.
- Event tap перевключается после `.tapDisabledByTimeout`.

## Звук

`AVAudioEngine`, tap устанавливается вне главного актора, буферы уходят через `AsyncStream`,
приводятся к 16 кГц моно. При смене микрофона (подключили AirPods) tap переустанавливается.
Уровень сигнала отдаётся плашке для волны. Выбор микрофона — в настройках.

## Вывод текста

**Три режима, по умолчанию первый:**

1. **Вставить сразу.** Текст вставляется в активное поле.
2. **Оставить в плашке.** Текст остаётся карточкой: перетащить куда нужно, скопировать, закрыть.
3. **Только в буфер.**

**Вставка — буфер обмена + ⌘V.** Самый надёжный способ для терминалов, Electron-приложений и
браузеров. Поле ввода Claude Code принимает только настоящую вставку, а посимвольно
«напечатанный» текст молча теряет.

1. Снимаем снимок всех элементов буфера.
2. Кладём текст с пометками `org.nspasteboard.TransientType`, `ConcealedType`,
   `AutoGeneratedType` и маркером сессии — менеджеры буфера и история Spotlight его не сохраняют.
3. Нажимаем ⌘V программно. Код клавиши V берём из текущей раскладки, а не считаем раскладку
   американской.
4. Возвращаем прежний буфер через 250–900 мс (терминалам нужно дольше), и только если в буфере
   всё ещё наш текст.

**Остальное:**

- В поле пароля (`AXSecureTextField`) не вставляем ничего.
- «Вставить последнее» — отдельная горячая клавиша, если вставка не туда или фокус потерялся.
- Авто-Enter после вставки — выключен по умолчанию, включается для выбранных приложений
  (удобно для терминала с агентом).

**Перетаскивание.** Карточку текста можно взять мышью из плашки, меню и истории и бросить в
любое приложение. Отдаём простой текст, не файл: Terminal при сбросе файла вставляет путь к нему.
Технически: `NSHostingView` с `acceptsFirstMouse`, чтобы первый клик в неактивном окне не
проглатывался; одна hosting view на панель (в macOS 26.2 вложенные теряют события мыши). Плашка
не прячется, пока идёт перетаскивание.

## Плашка

Общее для обоих стилей:

- `NSPanel` с `.nonactivatingPanel`: никогда не становится key-окном и не забирает фокус.
- Поведение окна: `.canJoinAllSpaces`, `.fullScreenAuxiliary`, `.stationary`, `.ignoresCycle` —
  видна на всех рабочих столах и поверх полноэкранных приложений.
- Кадр окна фиксированный и с запасом, анимируется только содержимое внутри. Так анимации
  плавные и окно не дёргается.
- Экран — тот, где курсор мыши.
- **Состояния:**
  - слушаю — волна;
  - живой текст;
  - оформляю — лёгкий блик по тексту;
  - вставлено — галочка и схлопывание;
  - ошибка — одна строка, что случилось.
- **Волна честная:** если микрофон ничего не слышит, она ровная, без декоративного «дыхания».
- Английские идентификаторы в живом тексте набраны SF Mono — сразу видно, что `useEffect`
  распознан как код.

**Пилюля.**

- Капсула над Dock по центру, `NSGlassEffectView`.
- Перетаскивается к левому или правому нижнему углу и запоминает место. У Wispr Flow
  неподвижная пилюля перекрывала кнопки и стала главной жалобой пользователей.
- Есть тёмный вариант стекла: живой текст должен читаться поверх любого фона.

**Остров у выреза камеры.**

- Чёрная форма, продолжающая вырез: вогнутые верхние углы, выпуклые нижние. Раскрывается
  пружиной.
- Форма своя, геометрия по мотивам `DynamicNotchKit` (MIT). Код GPL-проектов (boring.notch,
  VoiceInk) не копируем.
- На экранах без выреза (внешний монитор, iMac) остров прилипает к верхнему краю по центру
  под строкой меню.
- В полноэкранных приложениях вокруг выреза и так чёрная полоса — остров сливается с ней.

## Первый запуск

Отдельное окно. Ориентир — CleanMyMac:

- на каждом шаге один главный объект, одна главная кнопка внизу по центру;
- у шага свой глубокий цвет;
- анимация отвечает на действия человека, а не играет сама по себе.

Шаги:

1. **Привет.** Живой стеклянный объект — будущая «голосовая» форма приложения. Одна фраза о том,
   что это.
2. **Как выглядит.** Выбор стиля плашки: пилюля или остров. Рядом живое превью на мини-рабочем
   столе. Светлое или тёмное стекло.
3. **Клавиша.** Объёмная клавиша Fn на экране нажимается, когда человек нажимает настоящую Fn.
   Для этого хватает локального монитора событий, разрешение не нужно. Тут же выбор другой
   клавиши и проверка системной настройки 🌐.
4. **Микрофон.** Запрос разрешения, выбор устройства, честная волна: «скажи что-нибудь».
5. **Доступ.** Карточки Accessibility и Input Monitoring: зачем каждое, кнопка прямо в нужный
   раздел Системных настроек. Статус проверяется раз в секунду, галочка рисуется сама, как только
   доступ выдан.
6. **Модели.**
   - Whisper, 626 МБ: загрузка с докачкой, затем «готовим под твой Mac». Это один раз, может
     занять несколько минут.
   - Отдельной галочкой — «Умная структура» (+1,2 ГБ).
   - Пока идёт загрузка, можно перейти дальше: пробовать можно на системном движке.
7. **Попробуй.** Поле ввода: зажми Fn и скажи фразу. Видно живой текст и результат с
   оформлением.
8. **Готово.** Переключатель «запускать при входе», и окно сворачивается в иконку строки меню.

Онбординг можно открыть заново из меню.

## Строка меню, настройки, история

**Меню** (`MenuBarExtra`, стиль `.window`):

- состояние (готов / загружается модель / нет доступа);
- последняя диктовка карточкой, которую можно перетащить;
- пять последних из истории;
- ссылки на настройки и историю, выход.

С macOS 26 пользователь может скрыть иконку стороннего приложения из строки меню. Поэтому
повторный запуск приложения из Finder открывает настройки.

**Главное окно** — панель иконок слева, у каждого раздела свой цветовой мир:

- Главная — статистика и последние диктовки;
- История;
- Клавиша;
- Плашка;
- Текст;
- Словарь;
- Модели;
- Разрешения.

**История** (JSON-файл в Application Support):

- что хранится: сырой и оформленный текст, приложение, время, длительность;
- поиск, перетаскивание карточек, срок хранения;
- звук не хранится;
- небольшая статистика: сколько слов надиктовано и темп в словах в минуту.

**Запуск при входе** — `SMAppService.mainApp`. Состояние переключателя читается из системы, а не
из своего флага.

## Дизайн-язык

Дизайн сначала рисуется макетами и согласуется (этап 0 плана), до кода интерфейса.
Принципы, по которым рисуем:

- **Стекло — только на плавающих элементах:** плашка, панели, кнопки. Контент — текст, карточки
  истории — на обычной поверхности. Стекло на стекле не кладём.
- **Шрифты лежат в бандле** и регистрируются при запуске:
  - Onest (OFL) — интерфейс и крупные заголовки;
  - JetBrains Mono (OFL) — идентификаторы кода и цифры статистики.
- **Цветовые миры, как в CleanMyMac.** У каждого раздела и шага онбординга свой насыщенный фон:
  янтарный — главная, фиолетовый — история и вид, синий — клавиша, коралловый — микрофон,
  зелёный — доступ, бирюзовый — модели, морской — текст, розовый — словарь. Поверх —
  матовые стеклянные панели и крупный жирный текст. Слева узкая панель иконок.
- **Объёмные объекты.** Главный объект экрана — стеклянная 3D-модель (микрофон, клавиша,
  капсула, замок, чип). Рендер в Blender Cycles скриптами из `design/3d/`, в приложение попадают
  PNG из каталога ассетов.
- **Главная кнопка — круглая, светящаяся, внизу по центру.**
- **Текст интерфейса — короткий и по делу.** Без пояснений вида «Fn нажата — voicemode её
  слышит», без искр ✨ и эмодзи.
- **Движение — это ответ на действие.** Пружины `.snappy` / `.bouncy` / `.smooth` около 0,4 с.
  Ничего не анимируется ради анимации.
- **Честность.** Прогресс загрузки настоящий, волна ровная в тишине, ошибка называет причину.
- **Доступность.** При «Уменьшить движение» пружины становятся плавным появлением, волна — простым
  индикатором уровня. При «Понизить прозрачность» стекло заменяется непрозрачной поверхностью.
- **Звуки.** Короткие и тихие на начало, конец и вставку, отключаются.

## Приватность

Единственное сетевое обращение — загрузка моделей с Hugging Face, по явному действию в онбординге
или настройках. Ни телеметрии, ни аналитики, ни скриншотов экрана, ни отправки текста куда-либо.
История лежит локально и чистится по сроку.

## Решения, которые стоит назвать

**Whisper, а не Parakeet или GigaAM.** Parakeet v3 быстрее и на чистом русском точнее, но на
смешанной речи сваливается в английский целиком. GigaAM v3 лучший на русском, но ломает
английские слова. Нам важнее всего `useEffect` латиницей — это сильная сторона Whisper large-v3.
GigaAM может стать отдельным режимом «только русский» после MVP.

**Вставка через буфер, а не «печать» символов и не Accessibility API.** Печать теряет текст в
терминалах и в Claude Code. Accessibility API в Chromium и Electron-приложениях сообщает об успехе
и молча ничего не вставляет. Буфер с восстановлением работает везде, ценой 250–900 мс, когда
чужой буфер временно подменён.

**Живой текст — в плашке, в целевое поле уходит только финальный.** Стримить текст прямо в чужое
поле надёжно получается только в нативных полях с проверкой через Accessibility. В терминалах и
Electron — нет. Никто из сильных конкурентов так не делает.

**LLM — не для каждой фразы.** Полторы секунды на короткую команду агенту — это заметная пауза.
Для коротких фраз хватает пунктуации Whisper и RUPunct.

**Модели скачиваются, а не лежат в приложении.** Приложение с 2 ГБ внутри неудобно. Подготовка
модели под чип всё равно происходит на машине пользователя.

## Границы — что осознанно НЕ делаем в MVP

- Облачные движки и любые сетевые вызовы, кроме загрузки моделей.
- Распространение: Developer ID, нотаризация, DMG, автообновления (Sparkle).
- Mac App Store — невозможен без песочницы.
- Intel-маки.
- Режимы под отдельные приложения, кроме авто-Enter.
- Контекст с экрана: скриншоты, OCR, чтение открытого файла в редакторе.
- Словарь из текущего git-репозитория.
- Голосовые команды («удали последнее предложение»).
- Правка уже вставленного текста в чужом приложении.
- Дообучение своей модели структуры.

## Риски

| Риск | Что делаем |
|---|---|
| Turbo переводит английские термины в кириллицу | Замер turbo против large-v3 на 25 фразах владельца, словарь в prompt, замены по словарю на стадии 1 |
| Живой текст на русском «прыгает» | LocalAgreement-2, на экране фиксируются только согласованные слова |
| Подготовка модели Core ML занимает минуты и повторяется после обновления macOS | Отдельное понятное состояние в онбординге и меню. Запасной путь — whisper.cpp на Metal без этой стадии |
| LLM не успевает | Замерено: ~0,6 с на M3 Pro. Лимит 1,5 с, откат к стадии 4 |
| Стекло в окне без рамки «замерзает» (регрессия macOS 26.2) | Прототип плашки первым делом на этапе 4, проверка на 26 и 27 |
| Fn занята системной диктовкой или эмодзи | Проверка и подсказка в онбординге, альтернативные клавиши |
| Secure Input глушит event tap | Детект и сообщение в плашке. Сочетание через `KeyboardShortcuts` работает и там |
| Память: Whisper ~1 ГБ + LLM ~1 ГБ | LLM выгружается после 5 минут простоя и не скачивается без явного действия |
| Не установлен компонент Metal Toolchain (нужен MLX) | `xcodebuild -downloadComponent MetalToolchain` до этапа 6 |
